# Project Glossary

> **Owner:** Project Manager  
> **Status:** Maintained reference  
> **Last reviewed:** 2026-08-21

| Term | Meaning |
| --- | --- |
| Project Manager | Workflow, priority, status, blocker, and handoff owner; not a product, UX, implementation, security-review, or QA authority. |
| Codex Builder | Combined routine technical-planning and implementation role. |
| QA Agent | Independent exact-commit validation role. |
| CI | Automated validation run on every pull request. |
| On-demand specialist | Product Owner, Product Designer, Security Reviewer, independent technical reviewer, or External Consultant invoked only by a documented trigger. |
| Security Reviewer | Independent reviewer required for authentication, OAuth, Gmail, tokens, secrets, personal data, authorization, deletion, or deployment security. |
| Definition of Ready | Minimum evidence for the Builder to plan and implement, plus triggered pre-implementation approvals. |
| Definition of Done | Applicable exact-commit Builder, CI, QA, security, specialist, Project Manager, and Founder gates. |
| FEATURE-001 | Evidence-backed Gmail receipt-ingestion vertical slice and sole active implementation priority until complete. |
| Evidence | Source material supporting one or more recorded facts. |
| Provenance | Metadata distinguishing facts, inferences, and recommendations and linking their evidence. |
| Idempotency | Repeating the same operation creates no duplicate subscription or billing event. |
| ADR | Architecture Decision Record created only for consequential decisions. |
| Legacy role chain | Former mandatory PO → Designer → Tech Lead → Implementer → reviews sequence, now superseded by trigger-based routing. |

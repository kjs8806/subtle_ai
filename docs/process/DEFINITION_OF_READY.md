# Definition of Ready

> **Owner:** Project Manager  
> **Status:** Lean trigger-based implementation gate; supersedes mandatory approval by every specialist  
> **Last reviewed:** 2026-08-21

An issue is ready when its value, scope, priority, exclusions, and observable acceptance criteria are understandable; applicable known decisions are linked; material blockers are identified; and the Codex Builder can produce a concise plan.

Additional pre-implementation approval is required only when triggered:

- Product Owner for new/changed product behavior, ambiguity, prioritization, or scope conflict.
- Product Designer for meaningful flow, information-architecture, interaction, or UI decisions.
- Additional technical reviewer for unusually consequential/high-risk shared architecture or database changes.
- Founder for decisions reserved to Founder authority.

QA does not need to approve routine work before implementation. The Builder must flag untestable criteria, missing safe fixtures, security triggers, and material risks in its plan. The Project Manager confirms the issue, scope, stage, owner, blockers, and applicable evidence are linked.

# Architecture Decision Records

> **Owner:** Tech Lead
> **Status:** Active process
> **Last reviewed:** 2026-08-20

Use ADRs for durable, consequential architecture choices with meaningful alternatives or operational consequences. Smaller status questions may remain in `../TECH_DECISIONS.md`; an approved ADR should be linked from that register.

## Rules

- Name records `NNNN-short-title.md` using the next sequential number.
- Start from [0000-template.md](0000-template.md).
- Record context, decision, alternatives, consequences, security/data impact, migration/recovery, validation, owner, and approval.
- Use statuses Proposed, Accepted, Superseded, or Rejected.
- Do not edit an accepted decision to change its meaning. Add a new ADR and link the supersession.
- Founder approval is required when a choice materially changes cost, security risk, product scope, or delivery expectations.
